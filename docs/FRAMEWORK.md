# 当前框架与通信

更新日期：2026-11-03。通信版本 `tool_messages_v3`，工具版本 `table_programs_v2`。

正常流程：原图 → 理解 → 程序建索引 → 区域选择 → 程序提取 → 求解 → 按需换算坐标 → 答案核查 → 最多一轮由核查发起的定向内容返工。

|角色|正常输入|输出|
|---|---|---|
|理解|原图|全表HTML、不确定性|
|选择|原题、索引全表；B加原图，A仅文本|区域位置或工具查询|
|求解|原题、实际HTML子表、来源映射|答案字符串、可选坐标引用|
|核查|原图、原题、全表、选择、实际子表、候选答案及工具执行结果|错误观察、来源阶段和核查状态|

每阶段独立调用，不广播完整历史，不传参考答案或隐藏思考。正常求解不接收前序语义介绍。工具无法建立可靠网格/子表时，求解接收已解析消息中的原始HTML `tables`、`mapping_available=false` 与工具错误；不补造子表或来源映射。

## 通信与格式修复

保存原响应 → 去掉外层代码块/提取唯一JSON → 合并值完全相同的重复字段 → 检查执行当前接口必需的字段和类型 → 必要时由原角色最多额外修复两次格式。

冲突的重复字段不擅自取最后一个；错误信息明确指出冲突字段。修复仍用同一个模型与角色，只发送上次输出、具体接口错误和格式要求，不重复发送图片或全部上游历史。所有原始响应和修复尝试分别保存。在冻结实验配置不变的前提下，上游或工具反馈使当前输入变化时重新调用当前节点，不错误复用旧响应，也不因此终止样本。

`finish_reason=length` 不再直接拒收。JSON接口可读取就继续；无法读取才修复格式，程序不补造截断内容。不检查答案正误或核查status与issues的逻辑组合。不把无法解析的整段原文当作结构化消息传下去。

格式修复耗尽标记为 `execution_status=communication_failed`，保留最近可读取的求解答案及 `answer_origin`。该状态不代表核查通过；没有必要输入时不伪造输出。它默认在下次执行同一运行时重试，已完成的阶段复用。

## 工具执行与计数

选择只输出原表矩形范围。程序保持合并闭包扩展、完整 `source_rows/source_columns`、1起始位置和样本/表格版本/提取结果绑定。`regions=[]` 继续换成所有可索引完整表格。

HTML解析兼容可省略的行/单元格结束标签和展示包装，不增加原文中不存在的单元格。重叠合并、无法确定的网格位置等计算条件仍返回明确错误；其错误不自动触发理解返工或终止样本。

- 临时工具存储故障：同工具同参数最多额外重试两次。
- 无法执行的提取/坐标参数：反馈给调用者，最多额外两次当前工具参数修正；不重新跑完整上游链，也不占核查内容返工额度。
- 多次工具失败：保留原HTML、可用答案和真实错误，继续交求解/核查，标记 `tool_limited`。
- 工具查询和图片输入不设次数上限。当前 `inspect_cells` 查询HTML，不读取图片像素；未新增裁图/放大图工具。
- 查询与坐标映射按 `position_batch_size` 分批，默认64；这是批大小，不是任务总数量上限。原32区域、2000行、500列等固定任务失败阈值已取消。实际资源不足仍如实返回。

分别记录：`tool_queries`、`image_accesses`（实际图片附件次数）、`format_repairs`、`tool_input_repairs`、`tool_execution_retries`、`rework_rounds`。只由核查标签触发内容返工，累计最多一次。

## 坐标转换

重复使用同一引用可以正常替换；相同重复请求合并；未使用请求忽略。直接给出的原表坐标和其他数字不由程序改写。引用参数冲突/缺失时反馈求解智能体；已成功转换的部分不因其他请求失败被清空。无法转换的占位符保留并在工具错误中明确记录，交求解和核查处理，不生成虚假坐标。

## API与恢复

HTTP 400是当前请求不被接受，不直接停止分片。对服务明确返回的上下文超限，在输入消息/图片不变的前提下，把最大输出预算缩到服务报告的剩余空间并重发当前请求；实际调整保存在 `api_attempts.jsonl` 和响应 `_transport.request_adjustments`。输入本身已超限或不相关的400不盲目重复请求，记录当前通信问题并继续后续样本。基线和循环共用同一适配逻辑。

账户鉴权、错误端点等全局配置故障，以及持续服务不可用，仍保留现场并报告，不能伪装为模型成功。用户Ctrl+C始终可以停止并恢复。

`error.json`是诊断记录，不是永久跳过标记。通信失败默认下次重试；`--retry-errors`额外重试 `tool_limited`/旧 `tool_failed` 结果，正常完成的回答不重跑。替换失败记录前写入 `recovery_history.jsonl`，不抹去旧错误与已有答案。显式补跑工具失败时，`tool_retry_plan.json`保存该调用者及下游的重试范围和已使用的内容返工额度；上游可用阶段复用，旧阶段文件归档至`retry_stages/`。中断恢复复用本次补跑已经完成的节点，不再反复复用原来的失败参数，也不重置一次核查返工上限。`needs_revision`仅是模型核查结论，不是程序判定的运行异常。

每次实验仍固定代码、提示词、配置、清单与图像哈希。v3必须使用新运行名，不混写v2及旧结果。同模型M与基线的checkpoint、生成配置和图像策略保持一致；不得把不同总计算量称为等计算量比较。

## 批量完成与评估

四卡仍先完成四份循环，再启动四份基线。一个样本在本轮按已配置次数尝试后，通信/工具失败也保留为已处理记录；不会因其可在以后重试而永久挡住下一阶段。尚未处理的样本或全局服务故障仍阻止开始基线。

`completed`表示保存了终态结果，不表示回答正确；`errors`可与已保存结果重叠（例如保留答案的核查通信失败）。核查 `passed` 不是人工准确率。评估保留全部样本和失败状态，不删除失败来提高分数。

参考：[AgentScope故障处理接口](https://github.com/modelscope/agentscope/blob/v0.1.0/src/agentscope/models/model.py)、[AutoGen工具错误回执](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/agents/_assistant_agent.py#L1409)。上述重试次数是本项目显式配置，不是论文规定的最优值。
