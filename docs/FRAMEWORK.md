# 当前框架与通信

流程：原图→理解→程序建索引→区域选择→程序提取→求解→按需换算坐标→答案核查→最多一轮定向返工。

|角色|正常输入|输出|
|---|---|---|
|理解|原图|全表HTML、不确定性|
|选择|原题、索引全表；B加原图，A仅文本|区域位置或一次查询|
|求解|原题、实际HTML子表、来源映射|最终答案字符串、可选坐标引用|
|核查|原图、原题、索引全表、选择请求、实际子表、候选答案与坐标解析结果|观察、冲突、位置、错误来源阶段|

每阶段独立调用，不广播全部历史，不传参考答案，不传隐藏思考。正常求解没有前序语义介绍、题目解释或核查结论。只有求解返工才加旧回答与定向反馈。

选择只输出矩形位置；程序按合并闭包扩展区域、保留HTML和完整source_rows/source_columns。选择范围、程序实际范围分别保存，但尚未新增独立“原题目标清单”，也没有程序接管最终JSON生成。

核查标记understand/select/solve/unknown；主体按已知标签返回最早出错阶段，unknown不强行路由。理解返工重建索引并重选；选择返工重新提取；求解返工复用当前子表。原图正确性、目标是否正确、答案是否成立仍由模型判断。

JSON解析：保存原响应→提取唯一明确对象→接口字段/类型检查→原角色最多一次格式修复→仍失败则记录当前样本错误并继续后续样本。没有原文兜底，没有新格式转换智能体。表格工具只验证机械结构，不检查参考答案。

同模型实验通过role_apis把四个角色绑定到同一checkpoint和endpoint。即使求解只传文本，也不换成纯文本模型。provider特有参数来自模型profile，不再把GLM思考字段发送给所有本地模型。

算法、现有中英文提示词、核查顺序与返工机制沿用原版。本次是可迁移性与公平对照支持；此前讨论但未实施的目标传递、合并格导出改进，不能描述为已经完成。
